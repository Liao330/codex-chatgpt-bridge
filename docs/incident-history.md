## 2026-10-02：ChatGPT Web 重连提示未知客户端

日期采用 Asia/Shanghai 时区。事件类型为 `oauth_state_mismatch`，状态为已恢复。

用户在 ChatGPT 网页重新连接插件时看到：`Unknown client. Please reconnect from ChatGPT.`

### 已核实证据与根因边界

运行服务与默认磁盘状态不一致：runtime 文件记录的旧进程 PID 与端口监听 PID 不同；CLI 管理接口返回 HTTP 404；默认授权文件保存的 9 个客户端在运行服务中全部无法识别。

已确认根因层级为状态与运行实例不一致。旧进程实际使用的状态目录未查明，因此不能将目录漂移认定为已证实原因。

### 恢复与验收

恢复前创建受访问控制保护的状态备份，核实监听进程身份后定向停止该桥接进程。使用明确的默认 `C2C_STATE_DIR` 启动桥接，随后验证健康接口、管理接口和客户端识别。

重启后 4 个已保存的 ChatGPT 客户端均可识别；恢复操作未改变授权登记及令牌文件。用户随后在 ChatGPT 网页完成重新配对，连接成功，新令牌已持久化并经核验。恢复操作保留原授权数据，用户配对按正常授权流程新增令牌，两项验收分别完成。

### 复盘与后续

客户端未知错误应先检查运行实例与持久化状态的一致性；延长令牌期限不能修复实例未加载既有客户端的问题。启动前应核实工作区身份、端口归属与 CLI 管理接口，状态文件和运行进程之间的差异应作为诊断证据。

长期稳定方案状态：**已部署，即时验证通过；长期稳定性待自然运行观察**。2026-10-02 Asia/Shanghai 约 01:41 完成受控切换，登录启动入口已显式配置状态目录。原桥接进程保留，授权文件 SHA-256 在切换前后一致；仅精确停止原监督器及其已确认归属的隧道，未知归属的 SSH 进程保留。

实现包括固定状态目录、单实例互斥、桥接与 SSH 独立检查、进程身份和创建时间核验、受 ACL 保护的备份、仅对确认身份执行恢复，以及失败阈值、有界 CLI 调用和退避。

即时验收确认：CLI 管理接口正常且 running 为真，工作区和端口一致，tokenCount 为 4；公网健康接口返回正确工作区；中继自检全部 PASS；匿名 MCP 请求返回 HTTP 401。代码与切换脚本经 reviewer 审查，无阻断项。

测试证据为两组 Python 测试分别 22 与 39 项通过，以及 28 项监督器测试通过。Windows bash demo 一项依照既有平台条件跳过。C2C 的 186 项仅作为改动前通过的基线，不代表改动后重新执行了这 186 项。

授权策略保留 1 小时访问令牌和 30 天滑动刷新令牌，不承诺授权永不过期。真实 ChatGPT 工具调用尚未核验，长时间运行稳定性仍待自然运行观察；即时检查通过不能替代这两项验证。
